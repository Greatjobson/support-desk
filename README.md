# Support Desk — чат поддержки

Пользователь пишет о проблеме, получает автоматическое приветствие, ожидает оператора и общается с ним в одном диалоге. Обращение (Ticket) объединяет сообщения (Message), назначенного оператора и состояние работы. Сессия авторизации нужна для входа; она не является самим диалогом.

## Роли и границы

Клиент (requester) создаёт обращения, читает свои диалоги и отправляет сообщения. Оператор (agent) видит очередь, забирает свободное обращение, отвечает в назначенных ему диалогах и предлагает завершение. Автор сообщения определяется сервером из сессии. Проверка на фронтенде не заменяет серверную валидацию.

Первый выпуск включает текстовую переписку, шаблонное приветствие, очередь, назначение и завершение. Категории, язык, балансировка нагрузки, перевод другому оператору, оценки и админ — идеи для следующих версий. Сначала проверяем сценарий через HTTP, затем добавляем аккаунты, WebSocket и минимальный интерфейс. Это планируемое поведение, а не перечень уже готовых возможностей.

## 1. Первое сообщение

- Вход: действующая сессия клиента и текст проблемы. Отдельный заголовок необязателен для будущего интерфейса, его можно получить из текста.
- Результат: создан диалог в waiting и сохранено первое сообщение; клиент получает ID диалога и сообщения.
- Ошибка: пустой текст после удаления пробелов — сообщение и диалог не создаются. Отсутствующая сессия также отклоняется.

## 2. Автоматическое приветствие

- Вход: успешное начало нового диалога.
- Результат: система сохраняет одно сообщение «Приняли обращение, ожидайте оператора». Диалог, первый текст и приветствие создаются атомарно.
- Ошибка: сбой записи — вся операция отменяется; не остаётся пустого диалога или половины истории.

## 3. Очередь

- Вход: запрос авторизованного оператора на список свободных обращений.
- Результат: список waiting без назначенного оператора, сначала самые старые. Пустая очередь — нормальный результат.
- Ошибка: клиент пытается получить служебную очередь — доступ запрещён.

## 4. Подключение оператора

- Вход: сессия оператора и ID свободного обращения.
- Результат: обращение атомарно закреплено за оператором и получает in_progress. Переписка доступна владельцу и назначенному оператору.
- Ошибка: если другой оператор забрал первым, поздний запрос отклоняется: «Это обращение уже находится в обработке». Оба оператора не могут одновременно получить назначение.

## 5. Переписка

- Вход: ID диалога и текст от владельца или назначенного оператора.
- Результат: сообщение сохранено с ID, автором и временем; отправитель получил подтверждение. Другой участник получает сообщение через опрос или WebSocket. Ответ человека — отдельное действие, а не результат записи сообщения.
- Ошибка: нет доступа, диалог закрыт, текст пустой или длиннее 5000 rune — сообщение отклоняется. При разрыве соединения сохранённая история остаётся и догружается после восстановления.

## 6. Предложение завершить диалог

- Вход: назначенный оператор считает проблему решённой и отправляет запрос «Готовы завершить диалог?».
- Результат: состояние resolved — ожидание подтверждения; сохранён срок AutoCloseAt. Согласие клиента закрывает обращение. Любое обычное сообщение клиента возвращает in_progress и отменяет срок.
- Ошибка: посторонний оператор пытается запросить закрытие — отказ. Само по себе последнее сообщение оператора не закрывает обращение.

## 7. Закрытие по сроку ожидания

- Вход: наступил AutoCloseAt, запрос завершения актуален, статус resolved, последним написал оператор и после запроса не было ответа клиента.
- Результат: closed с причиной inactivity, системное сообщение о закрытии; задача снимается с активной нагрузки, история и назначение сохраняются. При явном согласии причина confirmed.
- Ошибка/отмена: если клиент уже ответил или ожидание отменено, старая проверка срока ничего не меняет. Согласие/ответ и автозакрытие обрабатываются атомарно.

Длительность ожидания — настройка, число часов ещё не выбрано. В waiting/in_progress молчание оператора или ожидание помощи клиентом не закрывают диалог. Уход пользователя из приложения тоже не закрывает его. Оценка не обязательна для завершения.

## Запуск учебного примера

```sh
go run ./cmd/api
```

Сейчас это консольный учебный пример модели и валидации. Функции чата реализуются поэтапно.
